# 0002. React Router 7 framework mode for "Remix (React Router v7 mode)"

- **Status:** Accepted
- **Date:** 2026-09-23
- **Brief:** §3 (stack), §7.1 (sessions), §7.5 (CSP)

## Context

The brief specifies "Remix (React Router v7 mode)". Remix v2 was folded into React Router v7:
the framework features (file routes, loaders/actions, SSR, sessions) now ship as `react-router`
7.x in "framework mode" with the `@react-router/dev`, `@react-router/node` and
`@react-router/serve` packages on Vite. The `remix` and `@remix-run/*` packages are in
maintenance. React Router 8 has since been released but the brief names v7, the ecosystem
(CSRF and session helpers, auth libraries) targets 7, and the RR team publishes a documented
upgrade path from 7 to 8.

## Decision

`apps/web` uses `react-router` 7.x in framework mode with `@react-router/dev`,
`@react-router/node`, `@react-router/serve` and Vite 7. Route modules export `loader`,
`action` and the default component in the usual way. Sessions use the `createSessionStorage`
API backed by Redis (brief §7.1). No `@remix-run/*` package is added.

React Router major updates are labelled `needs-adr` by Renovate (`renovate.json`).

## Consequences

- Documentation and error messages will say "React Router", not "Remix"; the brief's wording
  maps one-to-one.
- The migration to RR 8 is a known, documented path and can be scheduled once Phase 0 has real
  traffic and the auth/CSRF helpers we depend on have RR 8 releases.
- `.react-router/` (generated types) is git-ignored and regenerated by `react-router typegen`
  during typecheck.
